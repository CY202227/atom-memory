## 离线检索试点

取第一段完整对话 conv-26，保留全部会话，只评前 100 题；其中两题无证据标注，所以计分 98 题。
未按结果筛题，金标只用于计分；oracle 用原始对话逐条生成短原子，不使用问题或答案构造原子。
这是脚本原子下的证据召回，不是实际 LLM 固化能力、答案正确率或产品整体得分。

复现命令：

```sh
python -m atom_memory.eval.run_locomo /path/to/locomo10.json --consolidate oracle --score evidence --max-samples 1 --max-questions 100 --budget-chars 400 --out report.json
python -m atom_memory.eval.run_locomo /path/to/locomo10.json --consolidate oracle --score evidence --max-samples 1 --max-questions 100 --budget-chars 1600 --max-atoms 20 --out expanded.json
python scripts/diagnose_locomo.py /path/to/locomo10.json diagnosis.json
```

400 字符/5条：全部标注证据命中 42/98=42.9%，任一证据命中 57/98=58.2%。
1600 字符/20条：全部证据命中 50/98=51.0%，任一命中 68/98=69.4%。两参数同时变化，不能归因于单独预算。
这只是一个对话试点，不能代表完整十段对话，也不能与其他项目的官方排行榜直接比较。

## 原因诊断

诊断用相同对话重建实际 atom 库。42题通过；40题至少一条金标证据不在平铺 BM25 前100；16题金标在前100但超出前5。
没有失败题被归入金标 key 缺失或分层/预算裁剪。
诊断排序是 flat BM25、实际400字符召回是默认 layered，两者相同仅在此试点事实层数据中成立，不应推广到所有库。
主要改进方向是语义候选、实体/时间消歧、再次查找与详情展开，不应仅增大上下文。

## 真实模型试点

Velora 提供 scripts/run_live_memory_pilot.py，从已配置的模型连接读取凭据，不将凭据或私有地址保存进报告。
限定前三个会话，取其内有完整证据的前12题；真实固化后以答案 F1 计分。
真实模式不再强制将普通对话标成高显著性，且无进展会终止，避免保护原料造成无穷固化循环。
该题集、上下文和计分方式不同于98题 oracle试点，不能将得分变化当作直接提升。
模型别名不能证明实际模型身份；任何超时、固化或解析失败都必须报告，而非作为“通过”隐去。


2026-10-12 真实试点：前三会话、12个完整证据覆盖问题，单来源批次、120秒超时、1200字符/10条，模型别名 odb。
固化与问答运行结束，但12题全部回答 unknown（F1=0）；这不是能力验收通过，也不等于所有模型都会如此。
平均注入87字符，提示需要进一步验证保留/检索。再次只诊断固化时遇到 JSONDecodeError，快照未成功完成，不能据此断言原子数量或唯一根因。
之前大批次与较短超时试点也发生模型错误；现有连接的结构化固化表现不稳定。
真实报告与离线报告的题集及指标不同，不能把0和42.9直接作前后比较。


## 2026-10-12 修复复测

已修复：严格 Schema 与 Pydantic 校验；只对明确不支持 Schema 的接口降级到 JSON mode；取消任意请求错误后的无约束重试。非法 JSON、类型错误和截断分别处理，重试有界，失败不会消费来源。综合、画像、隐私重写及 LLM 召回也发送结构约束。历史 JSONDecodeError 没有保存原响应或结束原因，无法追溯确认唯一根因。

提炼改为保留来源语言、姓名与独立事实；不同经历不按文字相似度覆盖。词法检索加入通用英文 Snowball 词干与 IDF 覆盖排序，没有按测试答案添加同义词。来源自己的时间锚点用于相对日期，且不再把整段对话的时间表达派生到每个原子。

相同98题、400字符/5条的最终离线完整证据召回为45/98=45.9%，任一证据命中58/98=59.2%。改善有限，不能称为检索质量达标。

真实试点的全会话来源重跑在固化请求阶段失败（locomo-live-fixed）。随后把前三会话的全部58回合拆成连续6回合片段，保留模型额外参数与相同12题：初次2/12、F1=0.239；原文保留提示修复后13个原子、5/12、F1=0.406。分片条件不同于原先整会话来源的0/12，不能作严格因果比较；各轮模型返回和提炼结果也有变化。

新增 `/spaces/{uid}/sources/search` 提供历史来源片段；Velora memory_search 可据此查证原子未保留的事实。复用13个原子的快照和相同12题，不再提炼：初次回放8/12、F1=0.464；最终加入确定性来源时间派生后6/12、F1=0.578，平均内容字符1929.8（原子预算1200 + 来源预算2400）。这是更多证据预算、自动调用原文搜索的服务回放，不是400字符基线、也不是完整Velora自主工具决策评测。旧快照未存kind，回放统一补event；全部13个原子为L1。模型别名odb不能证明底层模型身份。

改变问答提示的试验曾降至3/12、F1=0.287，已恢复原来的问答提示，失败报告保留为locomo-live-answer-prompt-trial。命中判定为token F1>=0.5或金标词完整覆盖，并不等于人工确认的答案正确率；冗长回答、同义表达和日期格式会影响分数。慈善赛跑题原文写last Saturday，金标写Sunday，保留原金标未改分，记录这项不一致。

原文查证保留来源ID和历史状态；可能早于纠正，应优先明确较新的纠正，不能直接视作当前有效记忆。隔离、硬删除和预算已有回归覆盖。

仍需验证更大题集、完整Velora工具使用、提炼事实覆盖与模型回答稳定性。这些结果不支持宣称可靠长期记忆产品已验收。

## 2026-10-13 收尾：语义查证、完整工具流程与评分修正

旧 QA 报告的 hit/accuracy 含金标词覆盖条件，可能把“无法确认是否 single”误判为命中。这些数值只保留作历史记录，不能作为答案正确率。最新再计分见 `locomo-qa-rescored-2026-10-12.json`：只以 token F1>=0.5 计阈值命中，拒答、直接否定和请求错误不以词覆盖加分。原始 F1 仍会惩罚冗长的正确回答与同义表达，也不是人工真值判断。

实际 Velora 流程使用 RecallMemory、ComposePrompt、流式 Provider 和 LLMNode 工具循环；模型自行选择 memory_search/memory_expand。首次旧规则曾得到10/12，但再计分后原始回答平均F1仅0.195；该10/12不应引用为正确率。修复后的运行原始回答平均F1为0.181。另做不看金标的短答案提取，必须从回答中原样复制明确断言，不能把拒答中的替代选项提取成答案。再计分后的短答案指标为7/12达到阈值、平均F1=0.686。这个提取器也不是独立事实核验，不应宣传为58.3%或任何其他答案正确率。评测人格使用提问语言和两个只读记忆工具，并未写入私人会话。

语义来源检索只生成查询改写和已有片段键，不生成证据正文；输出保留原文、时间锚点、来源ID和历史状态。最多64个候选、24000字符模型索引；超出时明确返回candidate_subset，不宣称检查了全部历史。相邻对话上下文只在明确相同父来源与连续chunk时连接；重复chunk歧义不猜，删除前一来源后不会继续带出其内容。展开原子时优先截取匹配该事实的证据，不再总取来源开头。

第二段完整对话conv-30全部369个原始回合，切成71条来源，固定4来源/2400字符返回预算：前20题在加入上下文后，BM25完整证据命中14/20，语义16/20。接着预先固定尚未用于修改的第21–60题：BM25为25/40=62.5%，语义为30/40=75%；任一证据分别30/40和36/40，均无HTTP失败。模型只看问题和语料，金标dia_id仅用于评分。此指标是返回片段中是否包含标注证据，不是原子400字符召回，也不是最终问答正确率；替代有效证据和数据标注问题可能影响结果。

工程修复：不同偏好不再按文字相似度覆盖；精确去重同时比较类型、陈述、详情和日期。第三方昵称不会归入主用户称呼。具体检索失败保持空结果，只有“你记得什么”类清单请求才使用近期事实兜底。显式语义查找跨记忆层读取；未配置向量时可回退到语义，再失败仍保留词法查证，并分别报告部分失败。引用不存在或非当前批次来源的写计划会重试/失败，普通来源也不会被错误消费。

重新提炼前三会话58回合、相同12题的最终纯原子试点为5/12达到严格阈值、平均F1=0.502，仍有事实未保留。漏记复核试验为4/12、F1=0.432，没恢复画画事实且增加模型调用，故默认关闭；`ATOMMEM_CONSOLIDATE_REVIEW_SKIPS=true`仅作为可选实验。不能据此宣称固化质量已达标。后续需要更大范围的真实固化、不同模型/语言和人工证据支持检查。
